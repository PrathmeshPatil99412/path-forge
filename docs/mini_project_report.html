1. Title of the Project

PathForge: Heuristic and Blind Graph Search Optimization on Dynamic 2D Obstacle Grids — An Empirical Comparative Evaluation of A*, Dijkstra, BFS, and DFS

2. Problem Statement

Pathfinding in planar spatial topologies is an essential problem across artificial intelligence, autonomous robotics, automated guided vehicles (AGVs), automated logistics, and computer gaming simulations. Formally, given a discrete 2D grid workspace 𝕎 ⊂ ℤ2 of size R × C, the configuration space is partitioned into traversable free space ℂfree and impassable obstacle regions ℂobs:

𝕎 = ℂfree ∪ ℂobs,      ℂfree ∩ ℂobs = ∅

The space is represented as an unweighted, undirected graph G = (V, E) where each vertex v = (r, c) ∈ V represents a passable grid coordinate. Edges connect orthogonal 4-connected spatial neighbors with uniform transition cost w(u, v) = 1:

𝒩(r, c) = {(r-1, c), (r+1, c), (r, c-1), (r, c+1)} ∩ ℂfree

Given an initial source state S = (rs, cs) ∈ ℂfree and a target destination T = (rt, ct) ∈ ℂfree, the shortest-path problem requires finding an ordered sequence of vertices 𝒫* = ⟨v0, v1, …, vk⟩ such that v0 = S, vk = T, and the cumulative path cost is minimized:

L(𝒫*) = ∑i=0k-1 w(vi, vi+1) = k = min𝒫 ∈ Ω(S, T) L(𝒫)

Core Engineering Challenges:

  • State-Space Explosion: Blind uninformed algorithms (BFS, Dijkstra) expand radially in all directions. In open grids, finding a goal at distance d requires exploring 𝒪(d2) nodes, resulting in high CPU and memory consumption.
  • Concave Obstacle Traps: Complex topologies (such as U-traps or narrow corridors) present local minima where greedy heuristics can get trapped or unguided algorithms (DFS) wander into deep, unnecessary detours.
  • Optimality vs. Latency Trade-off: Identifying whether informed heuristic search (A*) guarantees global path optimality while minimizing the explored node count across diverse obstacle topologies.

3. Objectives

  1. Algorithmic Formulation: Implement four core search paradigms in Python 3: Breadth-First Search (BFS), Depth-First Search (DFS), Dijkstra’s Algorithm, and A* Search, without relying on third-party graph libraries.
  2. Mathematical Heuristic Formulation: Derive and prove the admissibility and consistency of the Manhattan Distance (L1 norm) heuristic for 4-connected grid topologies.
  3. Dynamic Simulation & Visualization: Develop an interactive web visualizer supporting dynamic wall placement, movable start/target nodes, procedural obstacle presets, and adjustable animation speeds.
  4. Automated Comparative Benchmarking: Build an endpoint (/api/compare) that runs all four algorithms simultaneously under identical grid conditions and records path length, nodes explored, execution latency, and success status.
  5. Software Validation: Construct automated unit test suites verifying boundary limits, obstacle collisions, Manhattan calculations, and disconnected target handling.

5. Algorithm & AI/ML Techniques Used

The system implements four distinct search algorithms covering both blind (uninformed) and heuristic (informed) graph search paradigms:

5.1 Breadth-First Search (BFS)

BFS expands the search frontier level-by-level using a First-In, First-Out (FIFO) queue (collections.deque). Because each grid step has uniform unit cost w(u, v) = 1, the path length increases monotonically with frontier depth. BFS guarantees finding the optimal shortest path on unweighted graphs:

L(𝒫BFS) = L(𝒫*),      \text{Time Complexity: } 𝒪(|V| + |E|)

5.2 Depth-First Search (DFS)

DFS explores deeply along each branch using a Last-In, First-Out (LIFO) stack before backtracking. DFS does not evaluate path costs g(n) or frontier depth. It commits to whichever orthogonal neighbor is processed first. As a result, DFS does not guarantee the shortest path and often produces suboptimal routes with high detour overhead.

5.3 Dijkstra's Algorithm (Uniform-Cost Search)

Dijkstra’s algorithm explores graphs with non-negative edge weights using a priority queue (min-heap) ordered by cumulative path cost g(n). On an unweighted 4-directional grid where all edge weights equal 1, Dijkstra's node expansion sequence mirrors BFS, but with min-heap maintenance overhead:

g(v) = \min_{(u, v) ∈ E} [g(u) + 1],      \text{Time Complexity: } 𝒪((|V| + |E|) \log |V|)

5.4 A* Heuristic Search

A* guides node expansion toward the goal by evaluating candidates using:

f(n) = g(n) + h(n)

where g(n) is the actual cost from the start node to node n, and h(n) is the heuristic estimate from node n to target T.

Manhattan Distance Heuristic: Because movement is constrained to the 4 cardinal directions (no diagonals allowed), the straight-line grid distance is given by the L1 norm:

h(n) = |r_n - r_T| + |c_n - c_T|

Admissibility & Consistency: The Manhattan distance represents the minimum possible steps between two grid points without obstacles. Any obstacle can only increase or maintain this distance, never decrease it (h(n) ≤ h*(n)). Because h(n) is admissible and consistent, A* is mathematically guaranteed to find the optimal shortest path while expanding fewer nodes than uninformed methods.

Algorithm Type Frontier Structure Shortest Path Guarantee Time Complexity Space Complexity
BFS Uninformed FIFO Queue Guaranteed (Unweighted) 𝒪(|V| + |E|) 𝒪(|V|)
DFS Uninformed LIFO Stack Not Guaranteed 𝒪(|V| + |E|) 𝒪(|V|)
Dijkstra Uninformed Min-Heap / Priority Queue Guaranteed 𝒪((|V| + |E|) log |V|) 𝒪(|V|)
A* Search Informed Min-Heap (by f = g + h) Guaranteed (Admissible) 𝒪(|E|) to 𝒪(|E| log |V|) 𝒪(|V|)

Min-Heap Tuple Ordering Invariant

When using Python’s standard heapq module, storing raw tuples like (cost, (r, c)) causes comparisons on the coordinate tuple whenever two nodes share identical costs. PathForge resolves this by inserting a monotonic counter:

\text{Heap Tuple: } (f(n), \; h(n), \; \text{counter}, \; (r, c))

This structure ensures that coordinate tuples are never compared, breaks ties in favor of nodes closer to the target (lower h(n)), and preserves FIFO order for identical scores.

def astar(rows: int, cols: int, start: Coordinate, end: Coordinate, wall_set: Set[Coordinate]):
    start_time = time.perf_counter()
    counter = 0
    h_start = abs(start[0] - end[0]) + abs(start[1] - end[1])
    pq = [(h_start, h_start, counter, start)]
    g_costs = {start: 0}
    parent = {start: None}
    visited = set()
    explored_order = []

    while pq:
        _, _, _, current = heapq.heappop(pq)
        if current in visited: continue
        visited.add(current)
        explored_order.append(list(current))

        if current == end: break

        for dr, dc in [(-1, 0), (0, 1), (1, 0), (0, -1)]:
            neighbor = (current[0] + dr, current[1] + dc)
            if 0 <= neighbor[0] < rows and 0 <= neighbor[1] < cols and neighbor not in wall_set:
                tentative_g = g_costs[current] + 1
                if tentative_g < g_costs.get(neighbor, float("inf")):
                    g_costs[neighbor] = tentative_g
                    h = abs(neighbor[0] - end[0]) + abs(neighbor[1] - end[1])
                    parent[neighbor] = current
                    counter += 1

9. Performance Evaluation

The benchmark data demonstrates significant differences across the four algorithms:

  • Search Space Reduction: On an unconstrained open grid, BFS and Dijkstra expanded all 700 cells to find the 53-step path. A* expanded only 54 nodes—a 92.29% reduction in explored state space while finding the identical optimal path.
  • Performance in Concave Obstacles: In the U-Trap scenario, A* expanded only 22 nodes to reach the target, escaping the pocket cleanly. Uninformed BFS and Dijkstra explored 292 nodes each. DFS suffered heavy branching overhead, visiting 629 nodes and taking 31.168 ms.
  • Path Suboptimality in Corridors: In Scenario 4, DFS took an exploratory side branch and produced a path of length 87 (+4 steps longer than the optimal length of 83 found by BFS, Dijkstra, and A*).

10. Analysis & Discussion

10.1 Heuristic Selection for 4-Directional Grids

The choice of heuristic is directly tied to the movement constraints of the grid:

  • Euclidean Distance (L2): √(Δr2 + Δc2) is admissible, but underestimates actual travel costs on 4-connected grids because diagonal steps are prohibited. This looser bound causes A* to expand more nodes than necessary.
  • Manhattan Distance (L1): |Δr| + |Δc| provides the exact minimal travel distance on an unconstrained 4-connected grid. This tighter lower bound focuses the search directly toward the target.

10.2 Robustness in Local Minima

Greedy Best-First Search (which uses only f(n) = h(n)) can become trapped inside concave obstacles as it prioritizes nodes closest to the goal. In contrast, A* balances heuristic guidance with accumulated cost (f(n) = g(n) + h(n)). As nodes inside a cul-de-sac accumulate higher g(n) costs, their overall f(n) values rise, allowing A* to naturally backtrack and route around the obstacle.

11. Conclusion

The PathForge mini project implemented, visualized, and empirically benchmarked four core graph search algorithms across multiple obstacle topologies.

The results confirm theoretical expectations: A* with the Manhattan distance heuristic consistently produces globally optimal paths while reducing expanded nodes by up to 92.3% compared to uninformed BFS and Dijkstra. Uninformed BFS and Dijkstra guarantee optimal solutions on uniform grids, but at the cost of expanding nodes across the entire space. DFS operates quickly on simple topologies but does not guarantee shortest paths and can produce severe detours and high latencies in constrained environments.
